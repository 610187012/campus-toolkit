# 資料模型（v2 定稿）

本文件為資料表與權限模型的唯一規格來源。舊模型（`students`／`parents`／`staff`／`admins`／`roster` 五個集合）已全面廢棄，資料備份後清除。

## 架構總覽

兩層模型：

1. **使用者帳號 1 張表**：無週期、永久。回答「這個人能否登入、怎麼登入」。兩階段驗證設置於此層。
2. **身分名冊 4 張表**（學生、家長、教職員、管理員）：以學年度、學期為小週期。回答「登入後的使用者以何種身分操作與使用功能」。

```
users（帳號，1筆/人）
  └─ uid ──> rosterStudents / rosterParents / rosterStaff / rosterAdmins
              （每期每身分 0~1 筆）
```

## 表 1：使用者帳號 `users`

`doc id = uid`。系統欄位 `createdAt`、`updatedAt`（非業務欄位），安全技術欄位 `lockIp`（鎖定綁定來源 IP，防換 IP 鎖號）。

| 欄位 | 鍵名 | 型別 | 說明 |
|---|---|---|---|
| 電子郵件地址 | `email` | string | 選填、**全站唯一**（小寫正規化）。登入識別＋2FA 收信；**與帳號至少填一個** |
| 帳號 | `account` | string | 選填、**全站唯一**。登入識別；**與電子郵件至少填一個** |
| 密碼 | `passwordHash` | string | bcrypt cost 12。**密碼只在這一層**，名冊不存密碼 |
| 2FA驗證 | `twoFactor` | enum | `off` / `email_notify` / `email_otp` / `totp`。實作附欄：`otpHash`、`otpExpiresAt`、`otpSentAt`（驗證碼暫存）、`totpLastCode`、`totpLastUsedAt`（防重放）、`totpFail`、`totpLockedUntil` |
| TOTP密鑰 | `totpSecret` | string | 靜態加密後存放（`enc:v1:…`，AES-256-GCM）；舊版明文於下次驗證成功時自動遷移。金鑰由 `TOTP_ENCRYPTION_KEY` 或 `SESSION_SECRET` 派生 |
| 姓名 | `name` | string | 帳號層姓名（建檔預設值；顯示以名冊姓名為準） |
| 登入紀錄 | `loginRecords` | number[] | epoch ms，新→舊，最多 50 筆。最後登入＝`loginRecords[0]` |
| 登入方式 | `lastLoginMethod` | string | `password` / `google` + `email_otp` / `totp` / `email_notify` |
| 登入次數 | `loginCount` | number | |
| CSS主題ID | `cssThemeId` | string | |
| 已安裝主題清單 | `installedThemes` | string | JSON 陣列字串 |
| 鎖定至 | `lockedUntil` | number | epoch ms，0＝未鎖 |
| 失敗次數 | `failedAttempts` | number | 達門檻寫入鎖定至 |
| tokenVersion | `tokenVersion` | number | 改密碼＋1，舊 session 全數失效 |
| 須先改密碼 | `mustChangePassword` | boolean | 管理員代設**預設密碼**時＝`true`（建立帳號、重設他人密碼），該員登入後由全螢幕遮罩要求先由本人修改；本人改密或一次性連結重設後＝`false`。缺省（舊帳號、Google 建立的帳號）＝不強制 |
| **慣用身分** | `preferredRole` | UserRole（保留） | 多身分時登入預設進入的身分。未設定或值不在候選內＝進選擇頁 |
| **狀態** | `status` | enum | `有效` / `無效`（介面顯示「停用」）。缺省＝有效，**≠ 有效即擋登入** |

**識別規則**：帳號無週期，只有「建立／刪除」與「有效／無效」。辨識鍵＝電子郵件地址或帳號
（至少填一個，另一欄可留空；兩者都填須指向同一帳號）。有值才查重，空值不參與唯一檢查。
無電子郵件的帳號仍可用「帳號＋密碼」登入；但忘記密碼信、Email OTP、登入通知與 Google
登入需信箱，此類帳號改由管理員重設密碼、2FA 用 TOTP。

## 表 2～5：身分名冊 4 張

集合：`rosterStudents`、`rosterParents`、`rosterStaff`、`rosterAdmins`
`doc id = ${uid}_${學年度}_${學期}`（一 uid 一期一表最多一筆）

### 共同欄位

| 欄位 | 鍵名 | 型別 | 說明 |
|---|---|---|---|
| 狀態 | `status` | `有效` / `無效`（介面顯示「停用」） | **擋該身分能否使用** |
| 電子郵件地址 | `email` | string | 該期該身分的信箱（展示／搜尋）；帳號無信箱則留空 |
| 帳號 | `account` | string | 該期該身分對應的**帳號名**（展示與銜接用）；建立時寫入，舊資料可能留空（靠 `email` 比對） |
| 姓名 | `name` | string | 該期該身分的姓名（**顯示以此為準**） |
| 學年度 | `academicYear` | number | 民國年 |
| 學期 | `semester` | 1 \| 2 | |

系統／關聯欄位：`uid`（連回使用者帳號）、`createdAt`、`updatedAt`。
帳號已刪除而條目保留時，`uid` 已查無使用者文件（稱「孤兒列」，見下方「孤兒條目與銜接」）。

### 各表專屬欄位

| 表 | 專屬欄位（鍵名） |
|---|---|
| **學生** `rosterStudents` | 學號 `studentId`、年級 `grade`、班級代碼 `classCode`、班級名稱 `className`、座號 `seatNo`、班號 `rollNo` |
| **家長** `rosterParents` | 學生姓名 `studentName`、學生電子郵件地址 `studentEmail`、學號 `studentId`、年級 `grade`、班級代碼 `classCode`、班級名稱 `className`、座號 `seatNo`、班號 `rollNo`、關係 `relation` |
| **教職員** `rosterStaff` | 屬性 `attribute`（教師/兼導師/兼行政/職員）、單位 `unit`、職稱 `title`、班級代碼 `classCode`、班級名稱 `className` |
| **管理員** `rosterAdmins` | 屬性 `attribute`（一般/超級，**「超級」只有超級管理員可以指派**）、指定功能模組 `modules`（陣列，**可選**：只存實際指定的內容、系統不自動補值；未指定＝除基本模組「系統設定」外無可用功能模組） |

### 功能模組架構（產品層級）

> 術語與「獨立開發 → 發表 → 安裝 → 啟用」流程、跨模組掛勾契約（系統公告、行事曆）見
> `主程式模組與功能模組.md`；本節只描述資料與權限層。

功能模組分兩層，註冊表不可混用：

- **產品層級** `src/types/feature-modules.ts`（`FEATURE_MODULES`）：回答「系統有哪些功能模組、
  哪些內建、哪些選用」。入口＝管理員首頁「功能模組管理」卡片 → `/admin/modules`
  （**卡片與頁面僅超級管理員可見可進**，見下方「功能模組選項（管理員）」）。
  - **內建**（`kind: builtin`，隨主程式提供、一律啟用；沒有「主程式功能模組」這層大項目，
    每個功能本身各是一張內建模組卡）：`account` 帳號、身分與安全管理、`users` 使用者帳號管理、
    `roster` 身分名冊管理、`settings` 系統設定、`schoolSettings` 學校基本設定、`miscSettings` 雜項設定、
    `classes` 班級管理、`announcements` 系統公告、`personalInfo` 學生個人資料、
    `activity` 稽核紀錄、`modules` 功能模組管理
    （管理端權限單位由 `types/modules.ts` 的 `MODULES` 派生，勿另抄清單）、
    `calendar` 行事曆。
  - **公告功能模組（期 A 已上線）**：
    - 資料：Firestore `announcements` 集合；設定 `settings/announcements`（分類、顯示方式、公告原則）。
    - 職權：管理員＝發佈／管理／設定（`/admin/announcements`，`requireAdminModule("announcements")`）；
      教職員＝收件＋發佈（可僅導師班）；學生／家長＝收件。四身分 provides 皆 true。
    - 跨模組接口：伺服器端呼叫 `src/lib/announcements.ts` 的 `publishFromModule()`；
      必填 `sourceModule`，只寫 `announcements`，受眾必須明確。
    - 收件 API：`GET /api/announcements`（role＋班級過濾下推）；
      教職員發佈：`POST /api/announcements`（班級受眾須含自己導師班）。
    - 顯示與否開關照功能模組機制；個人提醒介面見期 C。
    - **期 B**：收件匣套用設定的顯示方式（清單／「清單，置頂公告橫幅」／橫幅——
      置頂公告橫幅三行（標題 20 字／摘要 40 字／分類｜作者｜日期）、其餘單行清單；
      橫幅可本機關閉）；
      分類可排序（↑↓）；到期公告伺服端自動隱藏（管理端仍可見並編輯）；
      管理清單可依發布中／已封存篩選，並有關鍵字搜尋（省流閘門外，輸入即載入；
      封存／到期公告不進搜尋）。
    - **期 C**：個人公告提醒——收件匣「提醒我」；集合 `announcementReminders`
      （doc id＝`{announcementId}_{uid}`）；首頁鈴鐺（`AnnouncementReminderBell`）
      與提醒列表僅顯示「仍可閱讀」的公告；**非系統推播**（開啟頁面時才更新）。
      整套提醒的總開關為 `settings/announcements.defaultRemindersEnabled`
      （管理於「規則設定」卡片切換；關閉時鈴鐺與「提醒我」按鈕隱藏，
      `GET /api/announcements/reminders` 不讀取提醒資料、`POST` 回 403）。
      跨模組發文請呼叫 `publishFromModule()`（補修等模組上線時直接接此接口，勿自開集合）。
    - **期 D**：管理端入口更名，現全站統一稱「系統公告」（`types/modules.ts` 與
      `types/feature-modules.ts` 的 label 同步）。
      - **閱讀權限**：可多選身分（學生／家長／教職員）或獨立勾選 **「無」＝公開**
        （`isPublic`，不需先登入即可看見；與身分選項互斥，公開時一律全校、全身分）。
        讀取：`GET /api/announcements`（登入者，`audienceRoles array-contains role`）；
        公開公告的 `audienceRoles` 含全身分，故登入者亦由同一查詢命中。
      - **5 處顯示位置**（`settings/announcements.surfaces`，
        `Record<login|student|parent|staff|admin, { enabled, method, limit }>`）：
        系統首頁登入表單上方＋四種身分功能首頁（切換身分下拉選單下方、第一個登出按鈕上方）。
        每處由管理員個別設定「顯示與否／顯示方式（清單／「清單，置頂公告橫幅」／橫幅）／顯示筆數」。
      - **顯示 API**：`GET /api/announcements/surface?surface=…`（共用元件
        `AnnouncementSurface`）；`surface=login` 未登入可讀、只回 `isPublic==true`；
        其餘位置須登入，管理員功能首頁回全部發布中公告。
        查詢過濾下推＋15 秒 `cachedRead`（前綴 `announcements:surface:`，寫入後失效）。
    - **期 E**：管理頁設定改為四張可收合卡片（公告顯示方式／顯示位置／公告分類／
      規則設定），各卡片獨立儲存；新增搜尋框在「省流開關」閘門之外（輸入即載入）。
      「規則設定」含公告原則 `settings/announcements.policies`（三項布林，預設
      `enablePinned: true`／`forceExpire: true`／`hardDeleteExpired: false`）：
      啟用「置頂」（關閉＝新增與編輯皆不再允許置頂）；強制到期（到期留空時於
      `publishFromModule`／`updateAnnouncement` 補上發布後一個月）；下架真實刪除
      （封存與到期公告連同 `announcementReminders` 刪除；清掃用 `status=="archived"`、
      `expireAt<=now` 兩個單欄位查詢，於管理清單載入時執行；
      關閉＝僅隱藏保留、不進收件匣與搜尋）；
      以及個人提醒總開關 `defaultRemindersEnabled`（預設 `true`，見期 C）。
    - **期 F**：5 處顯示位置標題右側新增「全部公告 ›」入口 → 公告專頁
      `/announcements`（公開路由，未登入可讀；同頁依 session 呈現可閱讀範圍），
      不受各處「顯示筆數」（1～20）限制。
      `GET /api/announcements/archive`：未登入＝`isPublic==true`、一般身分＝
      `audienceRoles array-contains role`、管理員＝全部發布中；班級／到期記憶體過濾；
      單次 `limit(100)` 有界查詢＋15 秒 `cachedRead`（前綴 `announcements:archive:`，
      寫入後由 `invalidateAnnouncementsCache()` 清前綴）。
      分頁為共用元件 `components/ListPagination.tsx`（每頁 10/20/50/100、預設 10），
      純前端切片、翻頁 0 額外 Firestore 讀取；置頂圖示抽為 `components/PinIcon.tsx`
      （「規則設定」標籤與專頁清單同用）。
  - **選用**（`kind: optional`，由 `src/modules/<value>/module.json` 自動註冊，
    超級管理員以總開關啟用／停用）：先前手刻的五筆規劃佔位（spaceBooking、examRegistration、
    selfLearning、learningPortfolio、attendance）已移除（0.387），改由 manifest 註冊。
  - 狀態 `status`：`live` 已上線／`building` 開發中／`planned` 規劃中；
    為作者宣告的**展示資訊**：無入口（`href` 為空時不顯示「前往」齒輪按鈕）；
    可否啟用由超級管理員總開關決定（任何已安裝的選用模組皆可切換，預設未啟用）。
  - **作者與版本**（`author`）：每個模組皆有作者、作者資訊連結、版本號、版本（發布）日期；
    目前全站共用佔位資料（張家誠／https://github.com/takan003／1.0／2026-10-10 08:00），
    日後各模組可各自覆寫。頁面上收在名稱旁的 SVG 箭頭展開說明內，表格不加欄。
  - **提供功能**（`provides`）：產品層級、**唯讀**——由模組作者決定該模組有沒有做給該身分用。
    管理頁只能檢視、不能改。**預設＝教職員與管理員提供；學生／家長暫不提供**
    （可由模組作者日後調整）。
  - **顯示與否**：運維層級——有提供但暫時不開放進入／顯示。規則：
    `provides[role] === false` → 強制為「未提供」（顯示開關無效）；
    `provides === true` → 顯示開關生效，**缺省＝顯示**（欄位不存在＝啟用，fail-safe）。
  - **超級管理員完全不受限制**：`role === "admin"` 且屬性＝超級時，所有模組一律可見
    （不看 provides、不看顯示開關）；管理員首頁對超級直接顯示全部模組卡片。
  - 頁面 `/admin/modules` 是兩份**列表**（內建／選用各一張 table）：模組名稱旁的 SVG
    箭頭就地展開該列說明＋作者版本＋提供功能矩陣；選用表另有「總開關」欄；
    兩表各有四種身分（學生／家長／教職員／管理員）的**顯示與否**欄
    （提供功能＝否者顯示「未提供」文字，不可勾選）。
  - 選用模組總開關存 `settings/system` 的 `featureModulesEnabled` 欄位
    （`Record<模組代碼, boolean>`，只存選用模組；**欄位不存在＝一律未啟用**，
    與 `roleEnabled` 同屬覆寫時會保留的欄位）。
  - 每個模組對四種身分的**顯示與否**存同文件的 `featureModuleRoles` 欄位
    （`Record<模組代碼, Record<身分, boolean>>`，內建＋選用全部收錄；
    讀取時以註冊表 `provides` 裁剪；**有提供者只有明確的 `false` 才算隱藏，
    欄位不存在＝顯示**，同屬覆寫時會保留的欄位）。
  - **套用**：各身分首頁卡片依「提供功能 AND 顯示與否」過濾
    （`GET /api/settings` 回傳 `visibleModules`；管理員首頁另併「指定功能模組」權限）。
    **超級管理員完全不受限制**：不看 provides／顯示開關，首頁直接顯示全部模組卡片。
    API 維持「指定功能模組」守門，**不**因顯示關閉而額外阻擋（避免把自己鎖在門外）。
  - 讀寫走 `/api/admin/feature-modules`（GET／PATCH 皆 `requireAdminModule("modules")`
    ＋**僅超級管理員**；PATCH 兩種操作：`{ value, enabled }`＝總開關，僅「選用＋已上線」可切換、
    `{ value, role, enabled }`＝顯示與否，**提供功能＝否時不接受打開**；
    變更分別寫入稽核紀錄 `feature_module_updated`／`feature_module_role_updated`）。
- **管理端權限層** `src/types/modules.ts`（`ADMIN_MODULES`）：見下方「功能模組選項（管理員）」，
  是「內建功能模組」的管理權限層，由名冊「指定功能模組」指派。

### 功能模組選項（管理員）

`users` 使用者帳號管理、`roster` 身分名冊管理、`settings` 系統設定、`schoolSettings` 學校基本設定、`miscSettings` 雜項設定、`classes` 班級管理、`activity` 稽核紀錄、`modules` 功能模組管理。
**模組定義的單一來源是 `src/types/modules.ts` 註冊表**（分類 `category`、權限範圍 `scope`、入口 `href`、子功能 `children` 都在該表），
`types/users.ts` 的 `ADMIN_MODULES`／`BASE_ADMIN_MODULES`（scope＝core）／`SUPER_ONLY_ADMIN_MODULES`（scope＝superOnly）與管理員首頁卡片都由它派生；
這些權限單位在 `/admin/modules` 頁各列為一列「內建功能模組」。
超級管理員＝全開（權限由 `attribute` 判定，與 `modules` 內容無關）；
一般管理員＝僅被指定模組（`modules` 為可選欄位，名冊表單／批次只存使用者實際指定的內容，
未指定＝除基本模組外無可用模組，系統不代為補值）。
基本模組 `settings` 系統設定：入口對每位管理員（含一般屬性）一律顯示、不需指派；
系統設定實際可讀寫的設定項目**僅超級管理員**（`hasSettingsManage`），
一般管理員與其他身分頁內顯示「尚無可用設定項目」（可用功能日後再收斂）。
超級專屬模組 `schoolSettings` 學校基本設定、`miscSettings` 雜項設定、`modules` 功能模組管理、`stats` 統計儀表板：**僅超級管理員**可用——
不列入名冊表單的可指派清單（`SUPER_ONLY_ADMIN_MODULES`），

超級管理員對所有功能模組**完全不受「提供功能／顯示與否」限制**。
`classes` 班級管理（scope＝assignable、入口 `/admin/classes`）：版面比照「學校基本設定」——
`classes/layout.tsx` 共用外殼（標題區域、功能標題、返回／登出、頁尾），
內容頁直接放在 `/admin/classes` 底下（**無入口卡片層**）、共用同一套外殼。
頁面即班級總覽：當期各年級班級清單與每班學生人數
（唯讀、可搜尋）——讀 `settings/schoolClasses`＋當期 `rosterStudents`

（唯讀、可搜尋：座號／學號／姓名／班號／信箱／帳號，僅列當期有效條目），

舊代碼 `account`＝個人頁，個人頁已不需權限，故不再對應任何模組。）

### 管理員屬性的層級守門

「超級」屬性＝全站最高權限，**只有超級管理員可以指派或變更**
（`dal.checkAdminAttribute` → `roster.adminAttributeGuard`，非超級一律回 403）：

- 不得把屬性設為「超級」：名冊單筆建立／編輯、名冊批次新增與修改、
  帳號「同時建立身分」與帳號批次建立皆會擋（`/api/auth/me` 回傳 `adminAttribute`，
  管理員表單只對超級操作者顯示「超級」選項，表單端同步擋）。
- 不得修改、停用、刪除**既有的超級條目**（含批次列）。
- `POST /api/admin/create` 一律建立超級管理員，故非初始建立分支**須由超級管理員執行**
  （一般管理員無法藉此建出超級）。

另擋「動最後一位超級管理員」（`roster.lastSuperGuard`，以及帳號層的 `accountStatusGuard`
與名冊批次覆蓋模式的保留清單）：降級／停用／刪除最後一位超級前，須先有另一位超級管理員——
否則系統將無人可再指派超級（系統設定、學校基本設定無人可改）。

孤兒條目銜接同受管制：孤兒中若含超級條目，`/api/admin/roster/link` 與帳號頁的
「同時建立身分」／批次建立（`linkOrphanEntries`、`moveEntriesUid` 的 `allowSuper`）
非超級一律 403 或略過超級列，避免經銜接間接取得超級。

若既有資料**當期完全沒有超級管理員**，上述守門會讓「指定超級」也無從在介面完成
（此狀態下系統設定本就已不可用）：請至 Firestore Console 將某一筆
`rosterAdmins/{uid}_{學年度}_{學期}` 的 `attribute` 改為「超級」，
或執行 `scripts/reset-users-roster.mjs` 重建（會清空資料）。

### 唯一性

- `users.email`、`users.account`：**有值才查重**，各自全站唯一（兩者至少填一個）。
- 名冊條目：`doc id ＝ uid＋學年度＋學期` **由系統組出，天然唯一**，不受輸入欄位影響；
  檔案／表單「找到人」用的辨識鍵＝電子郵件地址或帳號（兩者都填須指向同一帳號）。
- 學號：單筆新增／編輯會檢查同一學期該身分不重複；批次匯入不檢查（重複一律放行，事後自行修改）。

### 孤兒條目與銜接

刪除帳號時名冊條目可保留（處理範圍「所有學期／僅本學期」），保留下的條目其 `uid` 已查無使用者文件——
名冊頁該列顯示**鎖鍊斷開圖示**（滑過顯示「無對應帳號」），即**孤兒列**（歷史學期條目在帳號刪除後同理）。

- **自動銜接**：建立單筆帳號（`POST /api/admin/accounts`）、批次建立／批次修改帳號
  （`POST /api/admin/accounts/batch`）、編輯帳號變更辨識鍵（`PUT /api/admin/accounts`）時，
  以**電子郵件地址＋帳號**兩個鍵找出孤兒條目，整批改掛到新 `uid`
  （改寫 `uid` 欄與 doc id `${uid}_${學年度}_${學期}`），回報筆數 `linked`。
  建立帳號同時選「身分」時**先銜接再寫入本期條目**（本期欄位以新填者為準，其餘學期舊條目一併接回）。
- **手動銜接**：名冊頁孤兒列操作選單的「銜接帳號」→ 查詢目標帳號 → 確認改掛；
  API `POST /api/admin/roster/link`（body `{ uid, key }`，`key`＝目標帳號的電子郵件地址或帳號）。
  查不到帳號時，先至「使用者帳號管理」建立同辨識鍵的帳號（建立當下即自動銜接）。
- 守則：**只接 `uid` 已查無使用者文件的孤兒**（仍活著的帳號一律不動）；
  目標帳號已有該學年度學期同身分條目時**跳過不覆寫**；改掛後回「已銜接 N 筆」。

## 表 12：學生本學期個人資料

學生可填寫的聯絡與家庭資料獨立存於 `studentPersonalInfo` 集合，**不寫入校方維護的
`rosterStudents` 學籍名冊**。文件 `doc id = ${uid}_${學年度}_${學期}`，每位學生每學期一筆。

| 欄位 | 鍵名 | 型別 | 說明 |
|---|---|---|---|
| 戶籍郵區／地址 | `householdPostalCode`／`householdAddress` | string | 郵區 3～6 位數字、地址最多 200 字，可留空 |

- 學生只可經 `GET/PUT/PATCH /api/student/personal-info` 讀寫自己的資料；伺服器驗證登入身分、文件 uid 與目前期間。
  管理端批次資料管理依選定學年度學期及學號／身分證精準匹配學生，新增僅補建缺少的該期文件、修改僅更新已存在的該期文件、刪除僅刪除該期文件並清理該期證件照；跨學期身分資料不隨刪除移除。不提供未限定辨識鍵的全表讀取。
- 管理端 Excel 範本以標題欄位自動辨識：每列有「學號」時優先使用學號，學號空白時使用「證件號碼」；「姓名」只核對選定學期的學生名冊，不寫回帳號姓名。民國年月日格式（如 `0990101`）匯入後轉存為 ISO 日期；範例列置於獨立工作表，避免誤當匯入資料。
- 帳號刪除沿用名冊處理範圍：`all` 刪除所有學期個人資料、`current` 僅刪目前學期、`none` 保留；單筆與批次刪除皆一致處理。
- 學期填寫規則存於 `settings/personalInfo_${學年度}_${學期}`，包含 `enabled`、`startDate`、`endDate`（`YYYY-MM-DDTHH:mm`，台北時間）、`target`、`allowAdmissionPhotoReplacement`、`allowGraduationPhotoUpload`；
  管理員經 `GET/PUT /api/admin/personal-info/settings` 維護。證件照操作除個別開關外，也須符合填寫狀態、日期與學生對象規則。開放狀態與日期區間須同時符合，
  起訖時間依台北時間計算，結束分鐘含當分鐘；每次寫入都由伺服器重新檢查。舊版只存日期的設定讀取時會轉為起始日 00:00、結束日 23:59。
- `target = { mode: "all" | "grades" | "classes", grades: string[], classes: string[] }`：預設 `all`；
  `grades` 模式以學生名冊 `grade` 欄位比對年級，`classes` 模式以 `classCode` 比對班級代碼。
  對象選項由 `settings/schoolClasses` 產生，伺服器讀寫時依登入學生自己的當期名冊條目執行比對，不掃描全校名冊。
- 欄位讀寫僅為單一學生文件點查／寫入，無列表查詢或跨學生掃描。
- 入學與畢業證件照經同源 `GET/POST /api/student/personal-info/photo` 讀取與上傳；伺服器驗證彩色 JPG、方向校正後至少 450×600 pixels（不檢查檔案內嵌的 dpi 資訊，該欄位多數相片不存在且與實際品質無關）。上傳前瀏覽器先自動縮圖（長邊 ≤1600 pixels、JPEG 品質 0.87）並移除 EXIF，原始檔上限 20 MB、縮圖後上限依儲存後端而定。
- 儲存後端由「系統設定 → 省錢專區 → 學生證件照儲存位置」決定，預設 `firestore`：照片本體存進獨立的 `studentPersonalPhoto` 文件（免費 Spark 方案可用，單張上限 900 KB），主文件只留指標。選 `firebase-storage` 時才需要 `NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET`，且專案須綁定 Blaze 並建立 bucket（**免費額度只存在於 `us-central1`／`us-east1`／`us-west1`**），每個 fork 使用自己的 bucket，避免不同學校共用照片儲存空間。
- 每張照片的 metadata 記載自己的 `backend`：管理員切換後端只影響「新上傳」，舊照片仍依其原後端讀取與刪除，不會因切換而失效。
- Firestore 後端的照片本體獨立存於 `studentPersonalPhoto` 集合，`doc id = ${uid}_${學年度}_${學期}_${kind}`，
  欄位為 `uid`、`academicYear`、`semester`、`kind`、`pointer`、`bytes`（Bytes）、`contentType`、`updatedAt`；
  主文件只留指標，避免每次讀學生資料都把照片一起載進來（見「資料庫讀取規範」）。
  Firestore 安全規則維持全站拒絕瀏覽器存取，照片只透過登入後的同源 API 提供。

## 狀態語意

- **狀態只有兩值**：`有效`／`無效`（介面稱「停用」）。舊資料的「停權」讀取時一律當作無效。
- **帳號狀態擋登入**：`users.status ≠ 有效` → 登入直接拒絕（一律回通用錯誤訊息，不透露帳號狀態）。
- **名冊狀態擋身分**：該期該身分 `status ≠ 有效` → 該身分不可選；當期名冊全無效或無條目 → 「當期名冊未建立或皆無效，請聯絡管理員」。

## 登入流程

1. `users` 查 1 筆（`email` 或 `account`）→ 狀態／鎖定／密碼。
2. 2FA（帳號層，登入時驗證一次）。
3. 查當期 4 表中 `uid` 相同且 `status=有效` 的條目 → 候選身分。
   - 0 筆 → 「當期名冊未建立或皆無效，請聯絡管理員」。
   - 1 筆 → 直接進入。
   - 多筆 → `preferredRole` 命中候選則直達，否則 `/choose-role`。
4. `session = { uid, role, entryId, period, candidates[] }`；稱謂與學號班級一律取自名冊條目。
   - `users.mustChangePassword = true` → 登入後立即顯示全螢幕「請先修改密碼」遮罩，
     改完（`/api/auth/change-password`）才放行；遮罩只擋畫面，其餘頁面照常。
5. 切換身分＝換 `role/entryId`（`/api/auth/switch-role`），不重驗 2FA。
6. `dal` 每請求校驗 `users.status` ＋ 當期名冊 `status`；`role=admin` 再取 `attribute`／`modules` 做模組授權。

## 管理端約定

共三個與帳號／名冊相關的功能（前兩個為管理員專屬模組，第三個每人一份）：

- **帳號、身分與安全管理**（個人頁，**不是模組、人人皆有**）：管理自己的姓名／電子郵件／帳號、
  密碼、兩階段驗證、慣用身分。學生／家長／教職員在各自功能首頁的 `／{role}／account`；
  管理員由首頁固定卡片（或「使用者帳號管理」頁的按鈕）進入 `/admin/admins`。
- **學生個人資料**（`personalInfo`，四身分皆提供）：首頁入口依「模組 × 身分顯示」設定控制；
  顯示本人當期名冊資料與帳號識別資訊，學生頁包含學號、年級、班級、座號與班號；
  讀取 `GET /api/me`，伺服器只回傳目前登入者自己的資料。
- **使用者帳號管理**（`users` → `/admin/accounts`）：管理員／被授權管理員專屬。
  全部使用者帳號的**單一工作表（無分頁）**：新增／編輯帳號、重設密碼、慣用身分、
  帳號狀態（啟用／停用）、刪除帳號（名冊條目處理範圍可選，見下）。
  - **單筆新增可同時建立身分**：表單下方「同時建立身分」選學生／家長／教職員／管理員，
    即帶出該身分的名冊專屬欄位（`rosterEntryFieldDefs`），建立帳號的同時寫入**當期**
    （目前學年度學期）名冊條目；不選＝只建帳號（事後至「身分名冊管理」指定）。
    API：`POST /api/admin/accounts` 的 `roster: { role, input }`，名冊欄位以
    `validateRosterInput` 驗證、帳號三欄以帳號輸入為準，學號查重用 `loadRosterIndex`。
  - **批次管理**：上傳 Excel／CSV（.xlsx、.xls、.csv，最多 900 列），
    三種模式「新增／修改／刪除」，以**電子郵件地址或帳號**辨識既有資料
    （兩者都填須指向同一帳號）；先「上傳預覽」列出逐列結果，再「確認執行」。
    新增可一併設姓名／密碼（**批次不檢查密碼命名規則**，僅須非空白）／帳號／慣用身分，並可填「**身分**」欄＝同時建立當期該身分
    （需一併填該身分的名冊專屬欄位，標題別名跨四身分合併，如「學號」「屬性」；
    學號查重只與當期**同身分**名冊比對，含本檔前列）；修改僅動姓名、帳號、慣用身分、狀態
    （空白＝不修改），**不支援批次改電子郵件與密碼**；刪除不可復原，名冊條目處理範圍
    （**所有學期／僅本學期／完全保留**）由確認視窗選擇，預設為所有學期。
    預覽與結果的「新增 N 筆」會標示同時建立身分的筆數（`rostered`）。
    刪除後以相同辨識鍵重建帳號，保留的名冊條目會自動銜接回新帳號（`linked`，見「孤兒條目與銜接」）。
    **執行時自動分批**：伺服器每批只處理一段（`offset` 起，上限：新增 120／修改 200／
    刪除 400 列），回傳 `progress`（`offset／processed／total／done`），前端依 `done`
    迴圈送下一批、遮罩即時顯示「已完成 x/y 列」；單批須在 300 秒（Vercel `maxDuration`）
    內完成。中斷（如逾時）時已建立的資料保留，**重跑同一檔已完成的列會自動略過**（可續傳）。
    API：`POST /api/admin/accounts/batch`（`mode`＋`dryRun`＋`file`＋`rosterScope`＋`offset`，
    後兩者分別僅刪除模式與分批執行使用）。
- **身分名冊管理**（`roster` → `/admin/roster`）：管理員／被授權管理員專屬。
  四分頁名冊（學生／家長／教職員／管理員）**含家長**，
  頁頂端為四種身分的啟用／停用（現行開關，存於系統設定；原「身分管理」併入）。
  - 單筆新增一律**綁定既有帳號**（一帳號最多四種身分，同身分同一學期僅一筆）；
    不建立新帳號、不設密碼——建帳號到「使用者帳號管理」。
  - 編輯僅維護名冊欄位；姓名／信箱／帳號（含密碼、慣用身分）唯讀，屬帳號層。
  - **批次管理**：上傳 Excel／CSV（.xlsx、.xls、.csv，最多 900 列），三種模式
    「新增／修改／刪除」，以**電子郵件地址或帳號**辨識該列（兩者都填須指向同一帳號）。
    名冊的唯一鍵＝**uid＋學年度＋學期**（doc id 由系統組出，欄位值不影響唯一性）；
    姓名、學號等其餘欄位重複可寫入；先「上傳預覽」列出逐列結果，再「確認執行」。
    - 新增（寫入方式二選一，預設「追加」）：只在**既有帳號**建立本期名冊條目——
      查無帳號（兩鍵皆無對應）之列略過並回報，不建立帳號、不設密碼；
      **姓名必填**，未填之列略過（不沿用既有帳號姓名）。
      - **追加**：保留同一學期既有條目，在其之上繼續增加，已存在者略過。
      - **覆蓋**：**先刪除同一學期既有的該身分名冊**，再依檔案新增（檔案＝完整名單，
        不在檔案內者本期該身分會消失）；選到覆蓋即顯示警語、預覽列出將刪除的筆數、
        確認鈕改為紅色「確認覆蓋」，確認對話載明刪除筆數與無法復原；
        預覽有任何略過列即禁止執行（避免清空後建不出來）；
        管理員身分保留自己的管理員身分與最後一位有效管理員（檔案包含者仍覆寫重建）。
    - 修改：只更新本期名冊欄位（含姓名）——除**辨識欄位**外全數可留空，
      空白＝不修改，只寫入有填值的欄位；本期無此身分之列略過；
      電子郵件、帳號、密碼不在批次範圍，請至「使用者帳號管理」維護。
    - 刪除：僅刪本期名冊條目，帳號與其他學期保留，不可復原。
    API：`POST /api/admin/roster/batch`（`mode`＋`strategy`＋`dryRun`＋`file`）。
  - 「停用／啟用」＝名冊層狀態（僅本期該身分）；「刪除」＝僅刪本期名冊條目，帳號保留。
  - **孤兒列**（查無對應帳號）在姓名旁顯示鎖鍊斷開圖示（滑過顯示「無對應帳號」），
    操作選單無「編輯」、改提供
    「銜接帳號」（＋停用／刪除）；銜接＝找回帳號後整批改掛，見「孤兒條目與銜接」。
- **兩種狀態分開調**：帳號狀態（擋登入）在「使用者帳號管理」；名冊狀態（擋身分）在「身分名冊管理」。
- 範例檔（`docs/範例_*.xlsx`，由 `/api/admin/downloads/[file]` 提供，依檔名分流權限）：
  使用者帳號管理四份（批次新增／批次新增含身分／批次修改姓名／批次刪除，
  三種模式皆有下載連結，新增模式有兩份）；
  身分名冊管理九份＝學生／教職員／管理員 × 新增／修改／刪除，
  九種組合皆有下載連結，頁面依「目前身分＋模式」吻合時顯示。
  家長由表單建立，不提供 Excel 匯入（`IMPORTABLE_ROLES` 僅 student／staff／admin）。
- 一般管理員未授權模組：API 回 403、首頁卡片隱藏（個人頁卡片不受模組限制；
  「系統設定」為基本入口、卡片一律顯示，其可設定範圍僅超級管理員；
  「學校基本設定」為超級專屬模組，卡片與頁面皆僅超級管理員可用）。
