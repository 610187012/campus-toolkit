# 公開前安全檢查與修補

> 檢查日期：2026-11-10  
> 範圍：A `campus-toolkit`、B `module-sdk`、C `campus-toolkit-marketplace`、E／F／G 模組

## 一、已具備的控制

1. **登入與 session**
   - `httpOnly`、`SameSite=Lax`、production `Secure`、`__Host-` cookie
   - JWT 絕對／閒置逾時、jti 撤銷、tokenVersion、角色開關、名冊條目驗證
2. **密碼與 2FA**
   - bcrypt cost 12
   - 重設 token 只存 sha256、一次性、有期限
   - Email OTP 只存 hash；TOTP T±1、90 秒防重放、5 次／15 分鐘嘗試限制
   - TOTP 密鑰以 AES-256-GCM 靜態加密（`TOTP_ENCRYPTION_KEY` 或 `SESSION_SECRET` 派生）
3. **CSRF**
   - 寫入 API 檢查 Origin／Referer 主機
   - SameSite=Lax
4. **Firestore**
   - `firestore.rules` 預設拒絕所有客戶端讀寫；伺服器一律 Admin SDK
5. **API 守門**
   - 主程式與模組的寫入 API 都有 rate limit＋CSRF＋鑑權
   - 模組 API 另有 `withModuleRuntime` 執行期第二道防線
   - JSON body 上限 1 MiB、檔案上傳 25 MiB；超過回 413，chunked 無長度時 fail-closed
6. **模組供應鏈**
   - ed25519 簽章、`keys.json` 固定公鑰、keyId 由公鑰計算
   - 安裝前 module-check、scanner validate-only、500KB、契約／版本比對
   - 簽章／公鑰／zip 內容／敏感檔檢查
7. **標頭與 CSP**
   - HSTS（production）、CSP nonce、X-Frame-Options、nosniff、Referrer-Policy
8. **其他**
   - `npm audit` 0 vulnerabilities
   - Actions pin 到 commit SHA
   - `.module-signing`、`.env*`、金鑰檔已在 `.gitignore`

## 二、這次發現並已修補

1. **模組安裝 zip 解壓**
   - 新增 zip slip 名稱檢查（絕對路徑、`..`、空片段）
   - 新增解壓後 10MB／2000 檔案上限，避免 zip bomb
   - tar.gz 先用 `tar -tzf` 驗證名稱再解壓
   - 拒絕解壓後的 symbolic link
2. **主題安裝 zip**
   - 解壓前先驗證 entry 名稱與未壓縮大小，不再先解壓才檢查
3. **C 的 release zip 驗證**
   - Windows 不再用 `Expand-Archive` 解壓未信任 zip；改用 .NET `ZipFile` 只列項目
   - Unix 與 Windows 都先檢查 zip slip，再進行後續驗證
4. **CSRF 強化**
   - 增加 `Sec-Fetch-Site` 檢查：`cross-site`／`same-site` 一律拒絕
   - 若設定 `APP_BASE_URL`，只接受該網域（降低 X-Forwarded-Host 偽造風險）
5. **CSV formula injection（F）**
   - 匯出的 CSV 對 `=`、`+`、`-`、`@` 開頭的值加 `'` 前綴
6. **祕密檔忽略規則**
   - `.gitignore` 增加 `*.key`、`*.jks`、`*.keystore`、`.npmrc`、`.netrc`、`id_rsa`、`id_ed25519`
7. **Storage 規則**
   - 新增 `storage.rules`：客戶端讀寫一律拒絕，檔案只由 Admin SDK 處理
   - `firebase.json` 已指向 `storage.rules`（部署時需 `firebase deploy --only storage`）
8. **App Hosting 用戶端 IP**
   - `K_SERVICE` 環境下自動信任 Cloud Run 的 `x-forwarded-for`（取最後一段），讓 rate limit 以真實 IP 為 key
9. **建立場次 500（可用性）**
   - read-stats Proxy 保留 `collection.doc()` 不帶參數時的自動 id，不再傳入 `undefined`
   - 這不是安全漏洞，但會讓管理端無法建立場次
10. **API request body 大小上限（P0-4）**
   - 新增 `src/lib/http-body.ts`：`readJsonBody` 串流計數，超限即中止並回 413
   - JSON 1 MiB、multipart／檔案 25 MiB、其他文字 1 MiB
   - `Content-Length` 格式錯誤或 chunked 無長度時 fail-closed
   - 主程式 JSON 路由與模組 runtime wrapper 都已套用；6 個 `formData()` 路由另加前置檢查
11. **TOTP 密鑰靜態加密（P0-5）**
   - 新增 `src/lib/totp-secret-crypto.ts`：AES-256-GCM，格式 `enc:v1:<iv>:<ciphertext>:<tag>`
   - 金鑰優先使用 `TOTP_ENCRYPTION_KEY`（32 bytes base64／base64url），未設定時由 `SESSION_SECRET` 以 HKDF-SHA256 派生
   - 舊版明文在下次成功驗證時自動改寫為密文；更換金鑰會使舊密文無法解密，需重新產生 TOTP 密鑰

## 三、仍接受的風險（公開前需揭露）

1. **模組不是沙箱**：模組仍 in-process、具伺服器權限；簽章與審核只降低上架前風險。
2. **`getAdminDb` 已在模組 API context 自動 scoped**：模組 handler 內的 `getAdminDb()` 會套用 `scopedDb`；宿主內部改用 `getAdminDbRaw()`。頁面（server component）不在 wrapper context 內，仍需頁面層 wrapper。
3. **頁面層 server-side 閘門已完成**：generated page／layout 轉接檔會先做 session、角色與非管理端 module gate，再呼叫原本頁面；不再只靠前端 `AdminSectionShell`。
4. **Rate limit 是進程內**：serverless 多實例會分割計數；高風險部署應加外部儲存。
5. **TOTP 密鑰已加密，但金鑰輪替需搭配使用者重設**：密文以 AES-256-GCM 存放；若 `TOTP_ENCRYPTION_KEY`／`SESSION_SECRET` 更換，舊密文無法解密，使用者需重新產生驗證碼APP密鑰。
6. **公開 API 沒有 opt-out**：目前所有模組 API 預設要求登入；未來若要公開 API 需新增 manifest 欄位。
7. **`xlsx` 來自 SheetJS CDN**：已 pin integrity，但不在 npm registry，`npm audit` 看不到。
8. **Storage 規則**：已新增 `storage.rules`（預設拒絕）；正式環境仍需在 Firebase Console／CLI 部署。
